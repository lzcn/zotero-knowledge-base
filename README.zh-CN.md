# Knowledge Base

<img src="addon/content/icons/icon-256.png" width="64" height="64" alt="Knowledge Base" />

[English](README.md) | **简体中文**

在 Zotero 中管理笔记、整理标签、发现相似条目。

## 安装

需要 Zotero 10。从 [Releases](https://github.com/lzcn/zotero-knowledge-base/releases/latest) 下载 XPI。在**工具**菜单中打开**插件**，选择**从文件安装插件**，然后重启 Zotero。

## 使用

在**工具**菜单中打开**知识库**，或使用文献库、PDF 工具栏中的按钮。

- **笔记：** 现有 Zotero 笔记自动出现，并关联来源和上级。右键**在知识库中打开**，或在设置中启用**原生笔记使用知识库编辑器**，即可在笔记标签页、独立窗口和 PDF 侧栏中使用同一编辑器。支持原生或 Markdown 编辑与自动保存。类型控件可切换文献、原子、思考和实体（默认），不添加类型标签。用 `[[ID]]` 连接笔记，可搜索或浏览图谱。笔记继承来源和上级标签。设置中提供**管理模板…**。
- **推荐标签：** 复用相关文献中的已有主题，并补充有依据的新主题。结合标题、摘要、已有全文特征、缓存原文和共享语义模型，按相关性、主题覆盖与重复程度决定展示数量。已有标签保留原拼写，新标签遵循句首大写／标题式及可选 # 前缀设置。
- **标签管理：** “整理相近标签”按名称变体、明确别名和语义匹配分组，直接展示原标签和匹配依据。“整理这组”只选中该组，预填使用较多的名称；核对保留名称与涉及条目后再合并。语义匹配需确认含义。合并、单个重命名和删除保留独立操作。“格式化”在上方标签列表逐行预览，保留固定拼写和结构，名称冲突跳过后单独合并。排除标签支持名称、`*` 通配和 `@colored`（当前文献库的彩色标签），用逗号或换行分隔。例如 `@colored, 待读*` 排除彩色标签及以“待读”开头的标签。规则共用于推荐、标签管理和笔记展示，不删除 Zotero 原标签。
- **相似条目：** 在本地查找相似文献，默认包含无全文条目，不自动连接笔记。macOS 语义检索会自动下载所需文件。

三个切换页共用同一个文献库运行时，各窗口共享索引和结果。启动时直接恢复完成后的检索缓存；未变文献复用向量和已保存结果，新增或变化的文献在后台更新。升级后首次启动会从已有索引生成新的缓存。设置页使用单色标题和细分隔线，图谱独立成节。状态区只显示缓存进度与各类型笔记数量。模板区为文献、原子、思考、实体四类笔记提供统一的下拉框，共用一个管理入口；各类独立选择，也可复用同一模板。未选择模板的类型保持空白。

图谱按笔记类型展示。结构表示手动整理的父子关系，引用表示笔记正文中的引用。结构关系以上级在上、下级在下的方式作为布局主干，同一分支保持聚拢并使用实线。引用使用虚线，布局拉力受限，避免大量引用压过手动结构。切换类型或关系选项会重新布局并适配视野。标签自动获得稳定的内部颜色，不修改 Zotero 标签颜色。每篇笔记根据标题与正文的文本相似度选择一个标签配色；匹配手动分组的标签优先，多个匹配仍按相似度选择。无标签节点使用中性色。底部图例已移除；关系列表显示标题，ID 保留在悬浮提示和复制入口中。

编辑器在**笔记信息**中保留来源、上级和标签。来源仅接受 Zotero 条目；上级决定层级。点击上级标题跳转，铅笔用于更换。标题保持单行，悬停显示全文。底栏显示类型和可编辑、可复制的 ID。原生与 Markdown 共用随窗口伸展的正文区。单击查看笔记，双击在独立窗口打开。图谱操作保留在工具栏和右键菜单。

点击来源旁的**边读边记**，打开 PDF 并在 Zotero 侧栏选中此笔记。**原生笔记使用知识库编辑器**统一控制侧栏、笔记标签页和独立笔记窗口，切换前会保存。PDF 工具栏空间不足时，工具收进**更多工具**。点击**摘图到笔记**，或按 Command-Shift-X（其他平台为 Ctrl-Shift-X）后框选图片；Escape 取消。图片保留 PDF 位置，不创建标注。新标注隐藏来源引用文字但保留元数据，已有内容不变。

## 备份

正文使用 Zotero 同步。ID、层级和链接保存在本机 `knowledge-base.sqlite` 数据库中。退出 Zotero 后备份其数据目录，包括此数据库和 `knowledge-base/` 文件夹。

资源统一由存储模块管理，在 Zotero 数据目录中的布局如下：

```text
knowledge-base.sqlite
knowledge-base/
  assets/
  cache/
    similar-items/
    coreml/minilm-l6-v2/
  models/minilm-l6-v2/
  runtime/onnx/
```

图片放在 `assets/`；检索与模型编译缓存放在 `cache/`；下载资源放在 `models/` 和 `runtime/`。目标目录不存在时会接续使用旧检索和 Core ML 缓存。独立 Related Work 的数据保留在原处。`-wal`、`-shm` 由 SQLite 自动管理。

schema 12 和 13 在同一事务中升级，原普通笔记归入实体。已有分类和标签保留。自动发现时保留原始正文、标签与位置，只读文献库保持只读。

## 开发

知识库的各种编辑入口共用同一个编辑器文档和原生笔记存储。`src/modules/editor-views.ts` 负责独立编辑窗口及共用的草稿、停止逻辑，`workbench.ts` 负责工作区导航。开启接管时，Zotero 原生笔记共用该编辑器；关闭后恢复原生布局。

固定拼写和明确的术语别名统一维护在 `addon/content/library/tag-terms.json`，格式化仅使用拼写表。标签操作复用已有文献索引和向量，不为缺失 PDF 原文临时索引或 OCR。语义模型不可用时使用文字规则。设置 `SW_HOST_NATIVE_MODEL_DIR=/path/to/local/model` 后执行 `npm run test:tag-semantics`，可用已有模型运行离线质量样例。

需要 Node.js 22.13+（22.x）或 24+。

```sh
npm ci
npm run check
npm run build
```

产物：`dist/zotero-knowledge-base.xpi`。

推理共用分词、切块、聚合和排序算法。`inference-backend.h` 负责 ONNX 执行与 CPU 回退，`coreml-backend.h` 提供 macOS 后端；Core ML 初始化或执行失败会回退到 CPU。目前原生打包支持 macOS，其他平台适配尚未实现。`SW_NATIVE_MODEL_DIR=/path/to/model node scripts/test-native.mjs` 使用临时缓存核对 CPU 与 Core ML 的向量和排序一致性。

`node scripts/benchmark-layout.mjs` 使用固定合成图测量后台布局耗时。

`node scripts/benchmark-search.mjs` 使用固定合成数据测量索引重建、指纹解码和检索，不读取个人文献库。排序摘要用于核对优化前后的结果；耗时不包含 Zotero 存储和原生模型推理。

检索使用 FastPriorityQueue 维护有界候选队列，评分与同分排序规则仍由插件控制。
