Manage literature notes, idea cards and your own thinking together in Zotero.

## Install

The manifest supports Zotero 7–10. Download the XPI from [Releases](https://github.com/lzcn/zotero-knowledge-base/releases), install it through **Tools → Plugins → Install Plugin From File**, and restart Zotero.

## Use

Open **Tools → Knowledge Base** to filter and create notes by type.

- **Literature Note**: one per literature item. Open it from the item pane; the first request creates it and later requests reuse it. A literature source is required.
- **Zettel**: one idea per card; an item can have multiple cards.
- **Thinking Note**: Ideas, Projects, surveys, article drafts and navigation. A source is optional.

All three types share the native editor, search, links, hierarchy and graph. A small label identifies each note type. The **Source · Zotero** label and native item icon identify the linked Zotero item; maintain its metadata in Zotero. **Parent note** controls the note hierarchy.

Write one idea per card, select its sources, and connect related cards with `[[ID]]`. `[[ID]]` stays visible and clickable; use `[[ID|your label]]` or `[your label](knowledge-base://card/ID)` to choose the link text. Cite items with `[@CitationKey]` to show a clickable author–year label; the key comes from Zotero, Better BibTeX or `Citation Key:` in Extra. Zotero notes use ordinary `[your label](zotero://select/…)` links. The browser starts with all cards; filter to entry points when needed. List previews and Back/Forward navigation help you return to an idea. Edit, Show in graph and Delete live in the top toolbar; the right pane focuses on reading. Preview images shrink proportionally to fit the pane. Each card has at most one parent; the graph shows hierarchy, references and sources separately. Choose connections directly in the graph; selections are saved. Drag the dividers to resize the card list and graph inspector. Hierarchy, outgoing links and backlinks are three collapsible groups.

Cards now open in Zotero's native note editor. Use its formatting, tables, images, citations and in-place math editing; select a formula to edit its LaTeX directly. The first heading is the card title. Zotero saves the note body automatically; card sources and connections save after a short pause. Save and `Ctrl/Cmd+S` keep the window open. `Ctrl/Cmd+K` finds a card to link. The **Insert** menu adds references without replacing the primary source.

Choose **Markdown** from the native editor’s **…** menu, following Better Notes’ toolbar integration. This entry is also available in Zotero’s own note sidebar, tabs and note windows, without Better Notes. Ordinary native notes remain outside Knowledge Base until you create or link a card; this switch only edits their existing content. Markdown saves automatically and `Ctrl/Cmd+S` saves immediately. Conflicting or interrupted drafts resume when you reopen Markdown.

Use **Markdown** for a single-pane source editor and **Native editor** to return. Both edit the same Zotero note. Math uses `$…$` or `$$…$$`, and ordinary tables use Markdown. Native images, located citations, annotations and rich formatting use protected links; keeping these links preserves their original data. Edit those objects in the native editor. Saving detects changes made in Zotero or Better Notes and retains your draft instead of overwriting them. An unchanged Markdown view does not rewrite the note.

The native editor is always WYSIWYG; there is no separate Browse mode. `Ctrl/Cmd+E` switches between Markdown and native editing. Ctrl/Cmd-click follows a link. `Ctrl/Cmd+W` offers Save, Cancel or Keep draft for pending card changes; already saved native note edits remain saved. Recovery drafts open as read-only previews until Save applies them. Conflicting drafts remain recoverable; **Save as new card** keeps both versions and copies embedded images.

Sources are optional for Zettels and Thinking Notes. Notes with a regular item source are filed beneath that item. Notes without a source are filed beneath a **Personal Knowledge** item in their own library. This parent groups your notes without becoming a literature source. You can rename it. A **Personal Knowledge** tag and a blue native color mark identify this parent; existing tag colors are retained. A source note attached to an item uses that item's parent; a standalone source note or source in another library stays linked while the card note remains under Personal Knowledge in its own library. Missing or trashed sources retain the note's last placement. Saving a selected source moves the existing note beneath it, even if the source has not changed. Clearing a source returns the note to Personal Knowledge without changing its identity. Plugin-created notes are organized on startup.

## Data and backup

Note bodies and embedded images use Zotero's native storage and normal sync. Card IDs, sources, hierarchy, graph links and drafts remain in `knowledge-base.sqlite` and do not sync through Zotero. Editing a linked note in Zotero refreshes the card locally. Deleting a plugin-created note moves it to Zotero's trash. Previously linked user notes remain protected when removed from Knowledge Base. Deleted or unavailable originals leave their cached content and relationships intact. Restore trashed originals from Knowledge Base, or save cached content as a new note if the original was permanently removed. Unavailable sources retain their keys until you explicitly relink them; the plugin does not automatically relocate these notes.

Quit Zotero before backing up the full Zotero data directory, including `knowledge-base.sqlite` and `knowledge-base/assets/`. The plugin starts with an empty knowledge base and only manages notes you create through it. It does not scan or import old library content; one-off library maintenance tools are kept outside the plugin. The former custom editor is retained under `src/ui/markdown-editor/` for development only; it has no UI entry and is excluded from builds and XPI packages.

## Development

Use Node.js 22.13+ (22.x) or 24+. Run `npm ci`, then `npm run check`.

- `npm run build`: reuse valid output when inputs have not changed.
- `npm run build:force`: rebuild from scratch.
- `npm run check`: formatting, lint, tests and type checking; reuse valid XPI output.
- `npm run release`: full checks, then prepare the XPI, `SHA256SUMS` and `updates.json` under `release/v<version>/`.

Build output: `dist/zotero-knowledge-base.xpi`. Install and verify changes in Zotero. `npm run test:host` checks startup, saving and shutdown using temporary profile and data directories; `ZOTERO_BINARY` selects another executable. Configure local paths in `.env` before using `npm start` for development.

Release preparation does not create a tag or upload files. Shared working rules live in the plugin workspace's root `AGENTS.md`.
