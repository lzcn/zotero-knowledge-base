Manage connected idea cards in Zotero, keeping sources and links between ideas.

## Install

The manifest supports Zotero 7–10. Download the XPI from [Releases](https://github.com/lzcn/zotero-knowledge-base/releases), install it through **Tools → Plugins → Install Plugin From File**, and restart Zotero.

## Use

Open **Tools → Knowledge Base**. Write one idea per card, select its sources, and connect related cards with `[[ID]]`. `[[ID]]` stays visible and clickable; use `[[ID|your label]]` or `[your label](knowledge-base://card/ID)` to choose the link text. Cite items with `[@CitationKey]` to show a clickable author–year label; the key comes from Zotero, Better BibTeX or `Citation Key:` in Extra. Zotero notes use ordinary `[your label](zotero://select/…)` links. The browser starts with all cards; filter to entry points when needed. List previews and Back/Forward navigation help you return to an idea. Each card has at most one parent; the graph shows hierarchy, references and sources separately. Choose which connections and sources to show in Zotero Settings; selections are saved automatically. Cards can also be created from PDF highlights.

Cards now open in Zotero's native note editor. Use its formatting, tables, images, citations and in-place math editing; select a formula to edit its LaTeX directly. The first heading is the card title. Zotero saves the note body automatically; card sources and connections save after a short pause. Save and `Ctrl/Cmd+S` keep the window open. `Ctrl/Cmd+K` finds a card to link. The **Insert** menu adds references without replacing the primary source; `/` commands are available in Markdown source.

Choose Reading view, Visual editing or Markdown source. Each mode fills the writing area, with white paper, native controls and compact connections. Source is a Markdown projection of the native HTML note: simple citations keep `[@CitationKey]`; complex citations, annotations and embedded images retain their structured HTML. Formatting may be normalized when applying source edits. `Ctrl/Cmd+E` toggles reading and editing; Ctrl/Cmd-click follows a link. `Ctrl/Cmd+W` offers Save, Cancel or Keep draft for pending source or card changes. Already saved native note edits remain saved. Conflicting source edits stay as recovery drafts; **Save as new card** keeps both versions and copies embedded images.

## Data and backup

Existing cards become real Zotero notes when first opened for editing; the original Markdown is retained in `knowledge-base.sqlite`. Converted note bodies and their embedded images use Zotero's storage and normal sync. Card IDs, sources, hierarchy, graph links and drafts remain in `knowledge-base.sqlite` and do not sync through Zotero. Editing a linked note in Zotero refreshes the card locally. Deleting a card moves its native note to Zotero's trash; restore a missing note there before editing its card.

Quit Zotero before backing up the full Zotero data directory, including `knowledge-base.sqlite` and legacy `knowledge-base/assets/`. Markdown file import and export are not supported.

## Development

Use Node.js 22.13+ (22.x) or 24+. Run `npm ci`, then `npm run check`.

- `npm run build`: reuse valid output when inputs have not changed.
- `npm run build:force`: rebuild from scratch.
- `npm run check`: formatting, lint, tests and type checking; reuse valid XPI output.
- `npm run release`: full checks, then prepare the XPI, `SHA256SUMS` and `updates.json` under `release/v<version>/`.

Build output: `dist/zotero-knowledge-base.xpi`. Install and verify changes in Zotero. `npm run test:host` checks startup, saving and shutdown using temporary profile and data directories; `ZOTERO_BINARY` selects another executable. Configure local paths in `.env` before using `npm start` for development.

Release preparation does not create a tag or upload files. Shared working rules live in the plugin workspace's root `AGENTS.md`.
