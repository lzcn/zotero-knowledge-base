Manage literature notes, idea cards and your own thinking together in Zotero.

## Install

The manifest supports Zotero 7–10. Download the XPI from [Releases](https://github.com/lzcn/zotero-knowledge-base/releases), install it through **Tools → Plugins → Install Plugin From File**, and restart Zotero.

## Use

Open **Tools → Knowledge Base** to filter and create notes by type. Search matches literal text in titles, bodies and keys, including Chinese substrings. Results prioritize exact keys and titles. Opening the browser automatically loads every managed note’s short summary in small batches. Only rows near the viewport are rendered; the selected note’s full body loads on demand. Individual edits refresh the affected summaries without reloading the list.

- **Literature Note**: one per literature item. Open it from the item pane; the first request creates it and later requests reuse it. A literature source is required.
- **Zettel**: one idea per card; an item can have multiple cards.
- **Thinking Note**: Ideas, Projects, surveys, article drafts and navigation. A source is optional.

All three types share the native editor, search, links, hierarchy and graph. Unsaved new notes offer Zettel and Thinking Note in the type selector. Saved notes display their type as plain text. Use **More (…)** to convert between Zettel and Thinking Note; the original note identity and previous keys remain valid. Literature Notes can only be created from a literature item. The **Source** label identifies the linked Zotero item; maintain its metadata in Zotero. **Parent** controls the note hierarchy. Source and Parent appear as compact clickable references; **More (…)** changes them. Source uses Zotero’s native CSL bibliography engine. Select an installed style in **Settings → Knowledge Base → Bibliography style**; open references refresh immediately. Author names, italics, numbering, DOI and URL fields follow the selected style. Choose **No parent** in the parent picker to detach a note. Parent appears above the full-width editor. Children, linked notes and backlinks stay visible with counts below the editor. Click a category to show or collapse its full-width list as clickable “title (key)” entries; long titles wrap across the available width.

Write one idea per card, select its sources, and connect related cards with `[[ID]]`. Every note keeps a unique internal ID. Its reference appears without brackets in the list, detail pane and editor; click it in the detail pane or editor to copy a `[[reference]]` link. Zettels use an automatic, read-only key. Thinking Notes also start with an automatic key, which you can edit beside the note type; `[[your-key]]` links to the same note. Changing a key preserves existing links and the internal ID. Literature Notes use `[[@CitationKey]]`, falling back to `[[ID]]` when the key is missing or duplicated. `[[ID]]` stays visible and clickable; use `[[ID|your label]]` or `[your label](knowledge-base://card/ID)` to choose the link text. Cite items with `[@CitationKey]` to show a clickable author–year label; the key comes from Zotero, Better BibTeX or `Citation Key:` in Extra. Zotero notes use ordinary `[your label](zotero://select/…)` links. The browser starts with all cards; filter to entry points when needed. List previews and Back/Forward navigation help you return to an idea. Edit, Show in graph and Delete live in the top toolbar; the right pane focuses on reading. Preview images shrink proportionally to fit the pane. Each card has at most one parent; the graph shows hierarchy, references and sources separately. The graph uses a force layout inspired by [Better Notes](https://github.com/windingwind/zotero-better-notes/blob/master/addon/chrome/content/libraryGraph.html): connected notes cluster together and frequently linked notes have larger nodes. Nodes retain their tag colors and stay visible when zoomed out. Labels keep a readable size and hide where they overlap. Hover or select a node to strengthen its connected links; other nodes and links retain their normal brightness. Visible titles are truncated to 20 characters by default, including the selected node; tooltips and the inspector retain the full title. Change **Settings → Knowledge Base → Graph title length** without using the config editor. Drag nodes to arrange them. Search highlights matching notes; click the background or press Escape to clear selection. Choose connections directly in the graph; selections are saved without resetting node positions or zoom. Enable **Hide isolated nodes** to show only nodes connected by the currently visible relationship types. The option is saved; hidden nodes return when it is disabled. Drag the dividers to resize the card list and graph inspector. Hierarchy, outgoing links and backlinks are three collapsible groups.

Open Knowledge Base from its icon on Zotero’s library toolbar or **Tools → Knowledge Base**. Choose **Zotero tab** or **Separate window** in **Settings → Knowledge Base → Open in**; the selection saves automatically and both entries follow it. Repeated requests reuse the chosen workbench, which shares note updates with other open editors. Select a note in the list to edit it directly, without opening another window. Switching notes saves current changes first; a conflict keeps the current editor open. Unchanged notes skip writes, and rapid navigation waits for editor initialization before selecting the last requested note. **More (…) → Open in Separate Window** opens a focused editor. Closing the workbench retains pending recovery drafts. Cards use Zotero’s native note editor. Its original layout, fonts and alignment are preserved. Use its formatting, tables, images, citations and in-place math editing; select a formula to edit its LaTeX directly. The first heading is the card title. Zotero saves the note body automatically; card sources and connections save after a short pause. Save and `Ctrl/Cmd+S` keep the window open. `Ctrl/Cmd+K` finds a card to link. Use the note-link icon in the editor toolbar to insert a linked note. Click the source reference to open its item; **More (…) → Change Source** searches sources and also offers **No source** for Zettels and Thinking Notes.

Click the Markdown icon at the left of the editor’s toolbar to switch modes; click it again to return to rich text. This entry is also available in Zotero’s own note sidebar, tabs and note windows, without Better Notes. Ordinary native notes remain outside Knowledge Base until you create or link a card; this switch only edits their existing content. Markdown is loaded only when requested, leaving ordinary native editing in control. Saves preserve the source text, cursor and scroll position without automatic formatting. Equivalent native HTML updates also preserve the source layout. Markdown saves automatically and `Ctrl/Cmd+S` saves immediately. Unchanged Markdown views follow saves from other windows; unsaved local changes retain conflict protection. Conflicting or interrupted drafts resume when you reopen Markdown.

Open views share note updates, and plugin writes to the same note are serialized. Markdown edits in different parts of the document merge automatically; overlapping edits keep the draft for recovery. A stale save keeps its draft. Links are updated only when their references change; changing their labels leaves the connections intact. A title shared by several notes stays unresolved: use an ID or unique key to choose the target. Changes refresh affected views, and graph positions remain stable when its connections do not change. Force calculations run in a background Worker while the graph remains interactive.

Markdown and rich text share one page and toolbar. Both edit the same Zotero note. Math uses `$…$` or `$$…$$`; the source editor keeps LaTeX as editable text and protects formulas from heading/emphasis styling. The native editor renders the formulas. Ordinary tables use Markdown. CodeMirror edits the whole Markdown document, including its title. Native citations, annotations and images appear as compact, atomic chips while their original HTML and metadata remain intact, following Better Notes. Edit those objects in the native editor. Saving detects changes made in Zotero or Better Notes and retains your draft instead of overwriting them. An unchanged Markdown view does not rewrite the note.

Markdown follows the native note font, size, line height and text width. Both editors have half a viewport of bottom space, so the last paragraph or formula can scroll toward the center without adding blank lines to the saved note. Click the eye icon for **Reading view**: the toolbar stays in place while the body displays rendered text, formulas and images. Click again to return to the previous editor with its draft, cursor and scroll position intact; entering Reading view does not save or format the note. `Ctrl/Cmd+E` switches between Markdown and native editing. Ctrl/Cmd-click follows a link. `Ctrl/Cmd+W` offers Save, Cancel or Keep draft for pending card changes; already saved native note edits remain saved. Recovery drafts open as read-only previews until Save applies them. Conflicting drafts remain recoverable; **Save as new card** keeps both versions and copies embedded images.

Sources are optional for Zettels and Thinking Notes. Notes with a regular item source are filed beneath that item. Notes without a source are filed beneath a **Personal Knowledge** item in their own library. This parent groups your notes without becoming a literature source. You can rename it. The plugin does not add tags or tag colors to this parent; your existing tags and colors are retained. A source note attached to an item uses that item's parent; a standalone source note or source in another library stays linked while the card note remains under Personal Knowledge in its own library. Missing or trashed sources retain the note's last placement. Saving a selected source moves the existing note beneath it, even if the source has not changed. Clearing a source returns the note to Personal Knowledge without changing its identity. Plugin-created notes are organized on startup.

On macOS, shortcuts use Command and leave Control available for native text editing and context clicks. Markdown saving waits for Chinese and other IME composition to finish. Two-finger scrolling pans the graph, pinch gestures zoom, and reduced-motion settings suppress layout animation.

## Data and backup

Note bodies and embedded images use Zotero's native storage and normal sync. Card IDs, sources, hierarchy, graph links and drafts remain in `knowledge-base.sqlite` and do not sync through Zotero. Editing a linked note in Zotero refreshes the card locally. Deleting a plugin-created note moves it to Zotero's trash. Previously linked user notes remain protected when removed from Knowledge Base. Notes in Zotero Trash keep their original library/key mapping, card ID and relationships. Restoring a note in Zotero reconnects the same card and any open editor, including after a restart, without reconstructing its content from Markdown. Once Zotero confirms that the original was permanently erased, the plugin removes its card and mapping; saved cached content is not offered as a replacement note. Unavailable sources retain their keys until you explicitly relink them; the plugin does not automatically relocate these notes.

Startup and each workbench opening, including reuse of an existing tab, check mapped notes against Zotero in small batches. Unchanged content skips reindexing and writes. The active list and graph exclude notes in Trash; choose **In Zotero Trash** to inspect their status or restore the original. These pages allow normal navigation without attempting to save a deleted original. Only selected notes mount their editor; list rows are rendered for the viewport. No note is automatically resurrected.

A durable save journal records card changes before updating Zotero. After interruption, startup completes the matching card metadata without rewriting note content. If either version has changed since the interrupted save, its draft remains available for recovery. This protects local cross-database saves; it does not sync the card database.

Quit Zotero before backing up the full Zotero data directory, including `knowledge-base.sqlite` and `knowledge-base/assets/`. The plugin starts with an empty knowledge base and only manages notes you create through it. It does not scan or import old library content; one-off library maintenance tools are kept outside the plugin. The former custom editor is retained under `src/ui/markdown-editor/` for development only; it has no UI entry and is excluded from builds and XPI packages.

Manage tags on the Zotero note or its parent. **Settings → Knowledge Base → Inherit parent tags** is enabled by default: notes display their own tags together with tags from Zotero parent items and ancestor cards. Inheritance is read live without copying tags into the native note; changes, moves and removals update the views. **Graph groups** lets you choose a tag and color per group and move groups up to set priority. The first matching group colors the note and clusters matching notes together; the graph legend shows the groups. Ungrouped notes use native Zotero tag colors or stable default colors. Tags containing spaces remain one tag. Hashtags in note text are ordinary content and never create or modify tags.

## Development

Use Node.js 22.13+ (22.x) or 24+. Run `npm ci`, then `npm run check`.

- `npm run build`: reuse valid output when inputs have not changed.
- `npm run build:force`: rebuild from scratch.
- `npm run check`: formatting, lint, tests and type checking; reuse valid XPI output.
- `npm run release`: full checks, then prepare the XPI, `SHA256SUMS` and `updates.json` under `release/v<version>/`.

Build output: `dist/zotero-knowledge-base.xpi`. Install and verify changes in Zotero. `npm run test:host` checks startup, saving and shutdown using temporary profile and data directories; `npm run test:cursor` compares native formula navigation and line-start insertion before and after integration, including a Markdown round trip. `ZOTERO_BINARY` selects another executable. Configure local paths in `.env` before using `npm start` for development.

Shared note snapshots and queued writes live in `note-sessions.ts`; scoped change notifications live in `events.ts`. `document-merge.ts` merges independent line edits with bounded work. `note-operations.ts` journals and reconciles native/KB saves. `search.ts` maintains a rebuildable SQLite bigram inverted index and keyset pagination, without FTS extensions; single-character searches use literal substring scans. `graph-layout-worker.ts` computes forces outside the UI thread. Schema 11 adds a rebuildable Trash availability cache alongside the save journal and search index, preserving existing cards, links and aliases. Tests cover concurrent and interrupted saves, draft rebasing, independent edits, indexed Chinese search, pagination, incremental links and Worker cancellation; the host test checks native-editor synchronization and restart recovery.

Release preparation does not create a tag or upload files. Shared working rules live in the plugin workspace's root `AGENTS.md`.
