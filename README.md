Manage literature notes, idea cards and your own thinking together in Zotero.

## Install

The manifest supports Zotero 7–10. Download the XPI from [Releases](https://github.com/lzcn/zotero-knowledge-base/releases), install it through **Tools → Plugins → Install Plugin From File**, and restart Zotero.

On confirmed Zotero quit, pending AI is cancelled and CLI processes are reaped. The quit barrier drains local drafts and queued note writes before database shutdown; restart preserves recovery drafts.

## Use

Open **Tools → Knowledge Base**, or use its library-toolbar button. Choose **Zotero tab** or **Separate window** in Settings.

- **Literature Note**: one note per paper, opened from the item sidebar.
- **Zettel**: one idea per card, with an optional source.
- **Thinking Note**: questions, projects, drafts and navigation.

Select a note to edit it with Zotero’s native editor. The first line supplies its title. Changes save automatically; `Ctrl/Cmd+S` saves immediately. Switch to Markdown with the editor toolbar button. Use **More (…)** to change the source or parent, convert Zettel/Thinking Note, or open a separate editor.

Search by title, body or ID; sort from the list toolbar. Back/Forward returns to previously opened notes. `Ctrl/Cmd+F` searches, `Ctrl/Cmd+N` creates a note, and `Ctrl/Cmd+Delete` moves the selected note to Zotero Trash. On macOS, `Cmd+Backspace` also works. Restoring a note from Zotero Trash reconnects its original card.

Link notes with `[[ID]]` or the link picker (`Ctrl/Cmd+K`). In native and Markdown modes, type `[[` to show notes, then keep typing to filter by title or ID. Choose with the arrow keys and Enter, Tab or a click; Escape dismisses the list. Pasting a copied `[[ID]]` into the native editor inserts the resolved note link with native undo and autosave. Unknown IDs remain literal text. Use `[[ID|label]]` for custom text and `[@CitationKey]` for literature citations. Edit **Note ID** to rename it; existing links stay valid. Source, parent, children, outgoing links and backlinks are clickable. Source formatting follows the citation style selected in Settings.

## AI (Experimental)

AI features are off by default. Open **Settings → Knowledge Base → AI Settings…** to enable them and configure DeepSeek, OpenCode Go or Codex. Disabling AI cancels analysis, clears open reviews and hides **Establish connections**, without deleting saved settings or login-manager keys. OpenCode uses only your [Go subscription](https://opencode.ai/v2/docs/console/go/); Console API and OpenCode CLI are no longer offered. Their existing saved configuration is left untouched. API providers use a key and model; Codex uses its installed program and login.

**Establish connections** remains the only AI action for a saved Zettel.

Connection analysis combines the complete title catalogue with local body-keyword retrieval, valid cached summaries, and nearby hierarchy or linked notes. The model can expand queries with synonyms and translations; local candidates remain eligible when title screening misses them. Up to 36 candidate summaries are ranked separately for organizational parents and substantive links. At most eight selected full notes are read to verify proposals. Summaries are cached only for unchanged title/body content. Analysis is cancellable and never applies changes automatically.

Review shows the relation type, its reasoning, an exact passage from each note, and the words that would become a link. Proposed parents also show the existing parent and the proposed hierarchy path. Quotes are checked against actual note bodies; fabricated evidence is rejected. Select changes explicitly to apply them. Existing words and formatting remain intact, existing links are not repeated, and changed notes or cyclic parents invalidate the proposal. Notes are limited to 60,000 characters for AI reads and combined full-text context to 180,000 characters. These checks verify grounding and workflow behavior; they do not establish semantic accuracy on every library.

## Graph and editing

Use **Global Graph** for the whole network or **Local Graph** for nearby notes. Click to select, double-click to open, drag to arrange, and scroll to pan. Pinch to zoom. Settings control local depth, title length, tag inheritance and graph groups. Group order determines the first matching color. Tags are read from Zotero; the plugin does not create them from note text.

Conflicting edits keep a recovery draft. Reopen to resolve the conflict, or use **Save as new card** to keep both versions. Notes without a source are stored under **Personal Knowledge** in their library; selecting or clearing a source changes placement without replacing the note.

## Data and backup

Note bodies and embedded images use Zotero's native storage and normal sync. Card IDs, sources, hierarchy, graph links and drafts remain in `knowledge-base.sqlite` and do not sync through Zotero. Editing a linked note in Zotero refreshes the card locally. Deleting a note in Knowledge Base moves its linked Zotero note to Zotero Trash, including previously linked user notes. The note disappears from Knowledge Base until restored in Zotero. Notes in Zotero Trash keep their original library/key mapping, card ID and relationships. Restoring a note in Zotero reconnects the same card and any open editor, including after a restart, without reconstructing its content from Markdown. Once Zotero confirms that the original was permanently erased, the plugin removes its card and mapping; saved cached content is not offered as a replacement note. Unavailable sources retain their keys until you explicitly relink them; the plugin does not automatically relocate these notes.

Startup and each workbench opening, including reuse of an existing tab, check mapped notes against Zotero in small batches. Unchanged content skips reindexing and writes. Lists and graphs exclude notes in Zotero Trash. Restore the original in Zotero to show the same card again. These pages allow normal navigation without attempting to save a deleted original. Only selected notes mount their editor; list rows are rendered for the viewport. No note is automatically resurrected. **Unavailable links** is a collapsed list beneath the workbench. It distinguishes targets in Zotero Trash from unresolved references and shows the active referring notes. Open a referring note to correct or remove its link. Restoring the original in Zotero reconnects it; a missing-target click never creates a replacement card.

A durable save journal records card changes before updating Zotero. After interruption, startup completes the matching card metadata without rewriting note content. If either version has changed since the interrupted save, its draft remains available for recovery. This protects local cross-database saves; it does not sync the card database.

Quit Zotero before backing up the full Zotero data directory, including `knowledge-base.sqlite` and `knowledge-base/assets/`. The plugin starts with an empty knowledge base and only manages notes you create through it. It does not scan or import old library content; one-off library maintenance tools are kept outside the plugin.

Manage tags on the Zotero note or its parent. **Settings → Knowledge Base → Inherit parent tags** is enabled by default: notes display their own tags together with tags from Zotero parent items and ancestor cards. Inheritance is read live without copying tags into the native note; changes, moves and removals update the views. **Graph groups** lets you choose a tag and color per group and move groups up to set priority. The first matching group colors the note and clusters matching notes together; the graph legend shows the groups. Ungrouped notes use native Zotero tag colors or stable default colors. Tags containing spaces remain one tag. Hashtags in note text are ordinary content and never create or modify tags.

Only the current database and Markdown fragment formats are supported. Other database schema versions are rejected without rewriting their contents; no historical schema or key conversion runs at startup.

## Development

`npm run test:connections:host` runs the AI connection workflow in disposable Zotero directories, including credentials, subprocess cancellation, reviewed application, restart persistence and shutdown cleanup. Provider responses are controlled fixtures; live service access is tested separately.

### Implementation

Ordinary note search uses the local SQLite character-bigram inverted index in `src/modules/search.ts`, exact key/title priority and literal substring verification; it uses no embedding model. `src/ui/graph-layout.ts` runs d3-force in a Worker.

Use Node.js 22.13+ (22.x) or 24+. Run `npm ci`, then `npm run check`.

- `npm run build`: reuse valid output when inputs have not changed. Run `make` in the parent workspace to build all three plugins.
- `npm run clean`: remove generated build output; retain downloaded tools, dependencies, research data and releases.
- `npm run build:force`: rebuild from scratch.
- `npm run check`: formatting, lint, tests and type checking; reuse valid XPI output.
- `npm run benchmark:graph`: compare Canvas and WebGL2 on the same 1200-node geometry in a disposable Zotero profile. Reports CPU submission time and display-frame intervals separately; `KB_GRAPH_BENCHMARK_OUTPUT` saves the JSON result.
- `npm run benchmark:loading`: measure repeated note audits, workbench opening and shared source rendering with 100 notes in a disposable Zotero profile; `KB_LOADING_BENCHMARK_OUTPUT` saves the JSON result. This measures a running host, excluding Zotero startup.
- `npm run release`: full checks, then prepare the XPI, `SHA256SUMS` and `updates.json` under `release/v<version>/`.

Build output: `dist/zotero-knowledge-base.xpi`. Install and verify changes in Zotero. `npm run test:host` checks startup, saving and shutdown using temporary profile and data directories; `npm run test:cursor` compares native formula navigation and line-start insertion before and after integration, including a Markdown round trip. `ZOTERO_BINARY` selects another executable. Configure local paths in `.env` before using `npm start` for development.

Shared note snapshots and queued writes live in `note-sessions.ts`; scoped change notifications live in `events.ts`. `document-merge.ts` merges independent line edits with bounded work. `note-operations.ts` journals and reconciles native/KB saves. `search.ts` maintains a rebuildable SQLite bigram inverted index and keyset pagination, without FTS extensions; single-character searches use literal substring scans. `graph-layout-worker.ts` computes forces outside the UI thread. Tests cover concurrent and interrupted saves, draft rebasing, independent edits, indexed Chinese search, pagination, incremental links and Worker cancellation; the host test checks native-editor synchronization and restart recovery.

Release preparation does not create a tag or upload files. Shared working rules live in the plugin workspace's root `AGENTS.md`.
