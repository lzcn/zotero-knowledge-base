Manage literature notes, idea cards and your own thinking together in Zotero.

## Install

The manifest supports Zotero 7–10. Download the XPI from [Releases](https://github.com/lzcn/zotero-knowledge-base/releases), install it through **Tools → Plugins → Install Plugin From File**, and restart Zotero.

## Use

Open **Tools → Knowledge Base** to filter and create notes by type.

- **Literature Note**: one per literature item. Open it from the item pane; the first request creates it and later requests reuse it. A literature source is required.
- **Zettel**: one idea per card; an item can have multiple cards.
- **Thinking Note**: Ideas, Projects, surveys, article drafts and navigation. A source is optional.

All three types share the native editor, search, links, hierarchy and graph. Change the type in the editor to reclassify a note; Literature Notes check their source and uniqueness.

Write one idea per card, select its sources, and connect related cards with `[[ID]]`. `[[ID]]` stays visible and clickable; use `[[ID|your label]]` or `[your label](knowledge-base://card/ID)` to choose the link text. Cite items with `[@CitationKey]` to show a clickable author–year label; the key comes from Zotero, Better BibTeX or `Citation Key:` in Extra. Zotero notes use ordinary `[your label](zotero://select/…)` links. The browser starts with all cards; filter to entry points when needed. List previews and Back/Forward navigation help you return to an idea. Each card has at most one parent; the graph shows hierarchy, references and sources separately. Choose which connections and sources to show in Zotero Settings; selections are saved automatically.

Cards now open in Zotero's native note editor. Use its formatting, tables, images, citations and in-place math editing; select a formula to edit its LaTeX directly. The first heading is the card title. Zotero saves the note body automatically; card sources and connections save after a short pause. Save and `Ctrl/Cmd+S` keep the window open. `Ctrl/Cmd+K` finds a card to link. The **Insert** menu adds references without replacing the primary source.

Use the **Browse / Edit** toggle or `Ctrl/Cmd+E`; both modes use Zotero's native note component, with white paper and compact connections. Ctrl/Cmd-click follows a link. `Ctrl/Cmd+W` offers Save, Cancel or Keep draft for pending card changes; already saved native note edits remain saved. Recovery drafts open as read-only previews until Save applies them. Conflicting drafts remain recoverable; **Save as new card** keeps both versions and copies embedded images.

Sources are optional for Zettels and Thinking Notes. Notes with a regular item source are filed beneath that item. Notes without a source are filed in a **Knowledge Base** collection. A source note attached to an item uses that item's parent; a standalone source note, missing source or source in another library stays linked while the card note remains in its own library's collection. Changing or clearing a source updates the note's placement without changing its identity. Plugin-created notes are organized on startup; old Markdown cards migrate when opened. Registered existing Zotero notes retain their original placement unless you explicitly change their source. Zotero's library view still includes all items, including notes organized in collections.

## Data and backup

Existing cards become real Zotero notes when first opened for editing; the original Markdown is retained in `knowledge-base.sqlite`. Converted note bodies and their embedded images use Zotero's storage and normal sync. Card IDs, sources, hierarchy, graph links and drafts remain in `knowledge-base.sqlite` and do not sync through Zotero. Editing a linked note in Zotero refreshes the card locally. Deleting a plugin-created note moves it to Zotero's trash. Removing a registered existing note from Knowledge Base keeps the original Zotero note; restore a missing note there before editing its card.

Quit Zotero before backing up the full Zotero data directory, including `knowledge-base.sqlite` and legacy `knowledge-base/assets/`. There is no import UI. Existing Zotero notes can be managed using their original identities, without copying their bodies; images, citations, tags and existing links remain intact. The former custom editor is retained under `src/ui/markdown-editor/` for development only; it has no UI entry and is excluded from builds and XPI packages.

## Development

Use Node.js 22.13+ (22.x) or 24+. Run `npm ci`, then `npm run check`.

- `npm run build`: reuse valid output when inputs have not changed.
- `npm run build:force`: rebuild from scratch.
- `npm run check`: formatting, lint, tests and type checking; reuse valid XPI output.
- `npm run release`: full checks, then prepare the XPI, `SHA256SUMS` and `updates.json` under `release/v<version>/`.

Build output: `dist/zotero-knowledge-base.xpi`. Install and verify changes in Zotero. `npm run test:host` checks startup, saving and shutdown using temporary profile and data directories; `ZOTERO_BINARY` selects another executable. Configure local paths in `.env` before using `npm start` for development.

Release preparation does not create a tag or upload files. Shared working rules live in the plugin workspace's root `AGENTS.md`.
